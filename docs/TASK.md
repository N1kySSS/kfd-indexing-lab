# Ускорь индексацию

Сервис получает список рекомендованных товаров. Перед показом необходимо убрать недоступные товары, исключения и повторения. Требуется написать функцию, которая формирует такую подборку.

## Основное задание (обязательное)

Работа выполняется в собственной копии [стартового репозитория](https://github.com/nikitosion/kfd-indexing-lab). В нём подготовлены тип `Product`, функция с `TODO` и два начальных теста. Реализация пишется с нуля; способ обработки данных выбирается самостоятельно. Начальные тесты сохраняются и дополняются. Команды запуска и места для ответов находятся в `README.md`.

```kotlin
data class Product(
    val id: Long,
    val name: String,
    val available: Boolean
)

fun selectProducts(
    products: List<Product>,
    recommendedIds: List<Long>,
    excludedIds: List<Long>
): List<Product> {
    TODO("Implement product selection")
}
```

Параметры функции:

- `products` — каталог товаров. Идентификаторы в каталоге уникальны.
- `recommendedIds` — рекомендации в порядке приоритета. Идентификаторы могут повторяться или отсутствовать в каталоге.
- `excludedIds` — товары, которые нельзя включать в подборку. Повторения и отсутствующие в каталоге идентификаторы допустимы.

Результат должен соответствовать следующим правилам:

1. В подборку входят только существующие товары с `available = true`, которых нет среди исключений.
2. Каждый товар встречается в результате не более одного раза.
3. Порядок определяется первым появлением идентификатора в рекомендациях. Порядок товаров в каталоге на результат не влияет.
4. Возвращаются полные объекты `Product` с исходными значениями полей.
5. Входные данные не изменяются. Если подходящих товаров нет, возвращается пустой список.

### Пример

| id | name | available |
| --- | --- | --- |
| 1 | Keyboard | true |
| 2 | Mouse | false |
| 3 | Monitor | true |
| 4 | Webcam | true |

```text
recommendedIds = [3, 2, 3, 99, 1, 4]
excludedIds = [1]
```

Результат — список из товаров `Monitor` и `Webcam`, именно в таком порядке. Товар `Mouse` недоступен, id `99` отсутствует в каталоге, `Keyboard` исключён, а повторная рекомендация `Monitor` не добавляет второй экземпляр.

### Проверка и сложность

Автоматические тесты должны проверять:

- обычную подборку и сохранение порядка при другом порядке каталога;
- повторяющиеся рекомендации и исключения;
- недоступные, исключённые и неизвестные товары;
- пустой каталог, пустые рекомендации и пустые исключения;
- случай, когда ни один товар не подходит;
- сохранность входных данных и независимость результатов повторных вызовов.

Ожидаемый результат в тестах задаётся явно. Сравниваются полные списки товаров, а не только их размеры. Несколько условий можно проверить одним тестом.

Решение должно учитывать объём данных: каталог может содержать десятки тысяч товаров, а рекомендации — сотни тысяч идентификаторов. Время выполнения и дополнительная память оцениваются через размеры трёх входных списков. Измерять время секундомером не требуется.

## Если хочется чего-то посложнее (необязательная часть)

Эта часть предназначена для тех, кто хочет задачу посложнее. Она выполняется по желанию и **не влияет на оценку работы**. Для полной оценки достаточно основного задания.

Требуется расширить собственное решение для сервиса, который обрабатывает много запросов к одному каталогу. Каталог загружается один раз и между запросами не меняется. Каждый запрос содержит свои рекомендации, исключения и параметр `limit` — максимальное число товаров в результате.

Все правила основной части сохраняются. Дополнительно:

- Возвращаются первые `limit` подходящих товаров.
- При `limit = 0` результат пустой. Отрицательные значения не поступают.
- Если подходящих товаров меньше лимита, возвращаются все найденные.
- После заполнения результата оставшиеся рекомендации не обрабатываются.
- Обработка нескольких запросов должна учитывать, что каталог у них общий. Данные одного запроса не должны влиять на другой.
- После загрузки нового каталога следующие запросы используют его данные.

В примере основной части при `limit = 1` результат содержит только `Monitor`, а при `limit = 10` — `Monitor` и `Webcam`.

Организация кода и способ вызова выбираются самостоятельно. Основная функция должна оставаться доступной и проходить свои тесты.

Для продолжения нужны проверки нулевого лимита, досрочного заполнения результата, нехватки подходящих товаров, нескольких запросов к одному каталогу и перехода на новый каталог. Досрочное завершение подтверждается числом просмотренных рекомендаций в тесте; эта проверка не должна менять результат функции.

В отчёте отдельно указываются стоимость подготовки каталога и стоимость одного запроса. Достаточно кратко объяснить, какая работа повторяется при запросах и от чего зависит число просмотренных рекомендаций.
