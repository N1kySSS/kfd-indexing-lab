## Основное задание

### Решение

**Файл с реализацией `selectProducts`:**

[Решение](src/main/kotlin/lab2/ProductSelection.kt).

**Как работает функция и почему выбран такой способ обработки данных?**

По заданию **excludedIds** может содержать дубликаты, для избавления от них используется `Set`, также он позволяет делать проверку `!in excludedSet` за константное время O(1).
Для начала проходимся по списку продуктов и фильтруем его (товар доступен и не находится в **excludedIds**), после чего преобразуем отфильтрованный список в `Map`, где
в качестве ключа используется `id` продукта. Это сделано для дальнейшей возможности получить элемент за константное время O(1). Использование здесь `Sequence` не является уместным,
поскольку он не дает выйгрыша по времени выполнения и памяти, даже несмотря на создание промежуточного списка после функции `filter`. По заданию сказано, что **recommendedIds** также
может содержать дубликаты, для их устранения он также приводится к `Set`, после чего по нему совершается поэлементный обход, если товар с таким id присутствует в списке доступных продуктов,
то мы добавляем его в результат.

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

Порядок рекомендаций и уникальность товаров гарантируется преобразованием входных списков в `Set` с использованием функции `toSet()`, которая под капотом использует следующую структуру данных: `LinkedHashSet`.
Исключенный и недоступные товары фильтруются этой строчкой кода: `.filter { it.available && it.id !in excludedSet }`, а неизвестные товары отбрасываются здесь: 
`val currentProductOrNull = availableById[currentId]
if (currentProductOrNull != null) {}`.

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях.

**Время выполнения:**

Преобразовать excludedIds в set: **O(e)** + преобразовать recommendedIds в set: **O(r)** + пройтись по этому set и выполнить константную операцию: **O(r)** + 
пройтись по списку продуктов, отфильтровать их и превратить в map: **O(2p)**. Суммарно получаем **O(e + 2r + 2p)**, что равняется **O(e + r + p)**. 
То есть линейной время, потому что в нотации **биг О** подразумевается асимптотическая сложность - константы отбрасываются. Стоит также учесть, что это оценка справедлива,
если:
+ операции с хеш-таблицами выполняются за O(1) в среднем
+ добавление в ArrayList стоит O(1) амортизированно

**Дополнительная память:**

+ excludedIds.toSet(): **O(e)** в худшем случае, если все id уникальны
+ промежуточный список после filter: **O(p)** в худшем случае, если все товары подходят
+ availableById (Map по id): **O(p)** в худшем случае, если все товары подходят
+ recommendedIds.toSet(): **O(r)** в худшем случае, если все id уникальны
+ result: **O(min(p, r))**

Итого дополнительная память (без result) равна **O(e) + O(p) + O(p) + O(r) = O(p + r + e)**. Константа 2 у p отбрасывается.
